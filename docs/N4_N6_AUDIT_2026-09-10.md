# N4–N6 Integrated Audit — Native Semantic Foundation

> Date: 2026-09-10
> Scope: commits `ef5d947` (N4), `9bcedd2` (N5), `f0b4dce` (N6)
> Decision: **N4–N6 accepted for their documented bounded scopes · implementation STOP · N7 NOT STARTED**

## 1. Audit objective

Audit the three consecutive native-semantic checkpoints as one foundation before any parallel-agent expansion. This audit verifies dependency continuity, identifies remaining promotion blockers, and separates accepted behavior from future work. It does not authorize or implement N7.

## 2. Checkpoint continuity

### N4 — authoritative bounded semantic read

Commit: `ef5d947` · canonical evidence: `docs/evidence/n4-native-semantic-2026-09-10.json`.

Accepted foundation:

- native `bridge.document.snapshot` on the active bound document;
- persistent document/entity PID binding;
- deterministic native↔Python document fingerprint parity;
- current-space semantic extraction plus recursively referenced block-definition content;
- representative core entity/resource extraction;
- typed oversized-response failure without silently killing the bridge.

N4 provides the parent-state oracle consumed by N5/N6. It does not mutate.

### N5 — bounded typed native mutation + R0 rollback

Commit: `9bcedd2` · canonical evidence: `docs/evidence/n5-native-mutation-2026-09-10.json`.

Accepted foundation:

- exact native allowlist: `entity.create.line`, `entity.update.line`, `entity.delete.line`;
- composite runtime-document + document PID + `expected_parent_fp` binding;
- persistent PID targeting for update/delete;
- native `DocumentLock` + transaction boundary;
- independent post-transaction semantic read-back;
- verified R0 `Transaction.Abort()` rollback;
- semantic document fingerprint schema v2 excluding volatile `saved/DBMOD`;
- pre-write capacity guard at the bounded extractor limit.

N5 is intentionally narrow. It does not provide generic command/eval execution or post-commit recovery.

### N6 — deterministic semantic validation + state chain

Commit: `f0b4dce` · canonical evidence: `docs/evidence/n6-semantic-state-chain-2026-09-10.json`.

Accepted foundation:

- deterministic created/modified/deleted PID delta;
- independent requested LINE geometry validation;
- allowed-effects validation by entity type and persistent target PID;
- target type/layer/style/hierarchy preservation on geometry-only updates;
- invariant document units/current-space/style-resource validation;
- new exact-duplicate geometry detection independent of Handle/PID identity;
- one tamper-evident `StateChainEntry` per accepted commit;
- verified rollback does not advance the chain;
- manual external drift is refused before native mutation dispatch;
- uncertain post-dispatch completion or semantic validation failure permanently blocks that executor run;
- append-only per-run JSONL evidence with `fsync`.

N6 changes no native bridge binary or native operation surface.

## 3. Integrated invariants that now hold

For the accepted N5 LINE scope, the full N4→N6 path now proves:

```text
bound live document
  -> authoritative semantic parent snapshot
  -> expected_parent_fp guard
  -> fixed-schema native transaction
  -> independent semantic read-back
  -> semantic delta / requested-effects validation
  -> COMMITTED_VERIFIED + one chain entry
     OR ROLLED_BACK_VERIFIED + no chain advance
     OR STATE_DRIFT / STATE_UNCERTAIN + stop
```

The live N6 acceptance on AutoCAD 2027 Session 1 proves create→update→delete chain continuity, rollback without chain advance, manual COM drift refusal, post-commit allowed-effects failure latching, and duplicate-geometry detection.

## 4. Remaining blockers / technical debt

### A. Post-commit recovery is absent — promotion blocker

N6 can detect a bad committed semantic outcome and latch `STATE_UNCERTAIN`, but it deliberately does not execute R1 inverse compensation or R2 checkpoint restore. A workflow that has already committed an invalid state cannot automatically return to a verified predecessor. This is the central later N7/NB5 problem.

### B. Crash/restart chain resume is absent — reliability blocker

The N6 journal is append-only and durable per append, but a fresh executor refuses a pre-existing non-empty journal instead of reconstructing and resuming a verified chain. This is correct fail-closed behavior for N6 but is insufficient for long-running production workflows across process restarts.

### C. Semantic extraction is bounded — scalability blocker

`MaxSnapshotEntities=32`; extraction is scoped to the active document's current space plus referenced block-definition content. This is sufficient for staged acceptance but not a whole-DWG/all-layout production oracle. Response payload remains bounded by the 65,536-byte transport frame.

### D. Native relations/topology are empty — semantic coverage blocker

The current native extractor emits an empty relation set. N6 therefore cannot legitimately validate intersections, adjacency, containment, connectivity or other topology through the authoritative native snapshot. Existing topology/fingerprint primitives must not be interpreted as live topology support.

### E. Mutation coverage is intentionally minimal — functional blocker

Only LINE create/update/delete is available through the native staged bridge. Layers, polylines, text, blocks, dimensions, hatch, transforms, layouts and 3D operations remain outside the native mutation surface.

### F. File-level integrity is not part of the state chain — recovery/persistence blocker

SaveAs/export/checkpoint promotion is not yet integrated with immutable artifact hashes and semantic state-chain advancement. NB8 remains open.

### G. Mutation retry/idempotency remains conservative

N6 correctly treats unknown post-dispatch completion as `STATE_UNCERTAIN` and forbids blind retry. There is no persisted mutation-request deduplication/resume protocol yet. This is safe but limits automated recovery from transport/process interruption.

### H. Acceptance-only fault injection must remain staged

`fault_stage=after_apply_before_commit` is a fixed enum used to prove R0 rollback. It is not arbitrary execution, but it should remain internal/testing-only and must not leak into any future public contract/promotion surface.

### I. Existing build/lint debt remains separate

The native build retains the known Autodesk-reference `MSB3277` warning families. Full-repository Ruff currently reports 14 pre-existing findings outside the N6 change set. N6 changed files pass Ruff; neither debt category is silently treated as resolved.

## 5. Audit conclusion

No N4–N6 regression or dependency break requires reopening a closed checkpoint. The three commits form a coherent staged foundation: N4 establishes authoritative bounded state, N5 establishes typed parent-guarded transaction/rollback, and N6 establishes deterministic semantic acceptance and chain continuity.

The architecture is **not production-promoted**. The remaining blockers above are real and should become future work only after an explicit next-phase decision. In particular, this audit does not convert N6 post-commit detection into a recovery claim and does not mark N7/NB5, NB8, NB9 or NB10 complete.

## 6. Parallel-development implication

Three-agent parallel work is viable only after freezing shared contracts for each wave. Parallel edits to native protocol definitions, semantic contracts and acceptance expectations would create false speed through merge/review ambiguity. The recommended model is therefore two production lanes in parallel plus one independent integration/acceptance lane, using separate worktrees/branches and immutable candidate commit SHAs. See `docs/PLAN_3_AGENT_NATIVE_SEMANTIC.md`.
